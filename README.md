# StashMuse｜「不怕吃灰」收藏夹

这是一个只运行在个人电脑的收藏整理器。浏览器扩展只读取用户已登录、已打开且已加载的页面内容；收藏最终保存在本机 D1（SQLite 兼容）数据库中。

## 已实现

- 收藏的统一本地数据模型：小红书、B 站、知乎、微博；收藏默认开启，点赞须手动选择且会独立标识。
- `待整理 / 已保留 / 稍后决定 / 回收站` 四种状态；来源失效仅可标记，不会自动删本地数据。
- 一级 / 二级分类；首次批量整理时 AI 直接把有效收藏归入层级目录并标记为已保留，用户仍可随时手动改动。
- JSON 安全导出、合并导入、完整恢复（不会恢复配对码等敏感设置）、可手动清空回收站。
- 每日从已保留内容中生成 1–3 条回看队列；同一天重复请求会复用队列，避免重复推送。
- 一次性配对码和 `127.0.0.1` 扩展导入接口；不读取、保存或上传 Cookie，也不开放局域网接口。
- 小红书同步会过滤当前账号自己的笔记、无标题卡片以及页面明确标记为已删除/隐藏/失效的内容；服务端会再次拦截这些无效条目。
- 独立「收藏展厅」页面：管理后台右上角可进入 `/gallery`。展厅以一级分类为顶部导航，使用统一的墨线纸张插画作为视觉中心；二级分类从主题图延展，点开后可在方形弹窗中查看已保留收藏、全选内容，或按场合 / 风格 / 颜色获得本地优先级灵感推荐。展厅直接读取同一套本地分类与收藏数据，不复制或上传内容。

## 本机运行

需要 Node.js 22.13 或以上。

```sh
cd stashmuse
npm ci
npm run db:generate
npm start -- --port 8787
```

打开 `http://127.0.0.1:8787`。由于 macOS 桌面文件提供器会让大量依赖读取卡住，`npm start` 会先把源码同步到 `~/Library/Application Support/collector-universe-runtime/project`，在该目录构建并运行。首次启动会复制原来的本地数据库；此后该运行目录的 `.wrangler/state` 是实际使用的数据库，后续启动不会用桌面旧数据库覆盖它。请勿手动删除这个运行目录。

## 安装同步扩展

1. 打开 Chrome 的 `chrome://extensions`，启用「开发者模式」。
2. 点击「加载已解压的扩展程序」，选择本项目的 `extension` 文件夹。
3. 在本地网页点击「配对扩展」，将得到的配对码填入扩展弹窗。
4. 用同一个 Chrome 账号登录目标平台，进入**自己的收藏页**。刷新扩展和页面后，可点击「一键同步当前平台」处理当前页面，也可点击「跨平台一键同步」批量处理已打开的收藏页；扩展会自动滚动采集、尝试点击「下一页」、按平台 ID 去重，最后导入并触发 AI 自动分类。

扩展不会进入账号页面，也不会同步点赞。页面的虚拟列表会卸载已滚出视野的卡片，因此扩展会在当前标签页会话中持续累积；分页平台会自动寻找「下一页」并继续采集，最多处理 80 页。从知乎“我的收藏”列表启动时，会依次进入每个收藏夹并完成各自的翻页采集；从具体收藏夹启动时，只同步该收藏夹。若平台弹出验证码、登录过期或页面没有标准的下一页按钮，需要按平台提示处理后再重试。当前同步器按平台独立选择器读取卡片链接：小红书、B 站、知乎和微博各自的 DOM 变化需要以实际账号页面做回归验证后维护。导入接口按 `平台 + 稳定来源键` 去重，重复同步只更新元数据；导入新内容后本地服务会自动触发 AI 批量分类。

## 可选 DeepSeek 分类

不配置密钥时，人工整理、搜索、备份、回收站和每日回看都正常可用。

如需 AI 建议，复制 `.dev.vars.example` 为 `.dev.vars` 并填入自己的 `DEEPSEEK_API_KEY`，然后重启本机服务。`.dev.vars` 已被 Git 忽略；也可以把密钥保存在 `~/Library/Application Support/collector-universe-runtime/secrets/.dev.vars`，避免源码压缩包包含密钥。密钥仅作为本机 Worker 的环境变量使用：不写入数据库、不随导出文件出现。

启用 DeepSeek 后，不同功能会按需发送收藏标题、作者、原链接、目录名、文字片段、公开页面正文或候选封面 URL。搭配助手最多选择少量公开封面让模型观察；不会发送平台 Cookie，也不会上传本地数据库文件。具体字段取决于用户主动触发的分类、摘要、沉淀、行动建议或搭配功能。介意第三方处理时，请不要配置 `DEEPSEEK_API_KEY`。

首次点击「AI 批量整理」时，AI 会根据收藏标题生成一级/二级目录，并分批返回分类、标签与置信度，结果直接写入本地收藏库并标记为已保留；不需要逐条确认。单条「AI 建议」仍可用于重新查看某条内容的建议。接口使用 DeepSeek Chat Completions 的 JSON Output，并会在本机校验目录 ID 与字段范围。[DeepSeek JSON Output 文档](https://api-docs.deepseek.com/guides/json_mode/)

## 每日知识卡片与行动回访

每天首次打开收藏展厅时，系统会从已保留内容中随机生成最多 3 张卡片，并排除「我想变美」目录及明显的变美内容；同一批卡片当天保持不变。后台点击外部发送时也会先生成今日卡片。

收藏展厅右上角的铃铛会显示今日卡片。展开后可以查看原文链接、摘要和来源，并选择「已看」「丢弃」或「下步行动」。行动方案会生成一条 15 分钟内可以开始的最小待办，直接显示在网页里，可标记为已完成。

留存反馈写入 `/api/retention`：`read`（已看）与 `not_interested`（丢弃）。行动方案写入 `/api/action-plans`，后台会显示已生成和已完成行动的具体计数。

## 外部推送

飞书推送默认关闭。用户自行配置后，管理后台可把「每日知识卡片」发送到指定飞书群机器人；发送内容包括卡片标题、摘要和原始链接。macOS 用户级定时任务每天 09:00（电脑本地时区）运行，先生成今日卡片，再发送到飞书；同一天重复执行不会重复发送。安装或更新定时任务：`node scripts/install-daily-feishu.mjs`。电脑需开机并联网；睡眠期间错过的任务会在唤醒后执行。后台仍可手动点击「立即发送到飞书」。

在本机 `.dev.vars` 或 `~/Library/Application Support/collector-universe-runtime/secrets/.dev.vars` 设置 `FEISHU_WEBHOOK_URL`，重启本地服务生效。机器人若启用关键词校验，请加入「今日知识卡片」；若启用签名校验，当前发送器还需配置签名才能发送。Webhook 是凭据，不要写入源码或公开分享。任务日志保存在 `~/Library/Logs/CollectorUniverse/`。

## StashMuse Agent Skill

仓库内包含通用 Agent Skill：`skills/stashmuse/`。它采用标准 `SKILL.md` 结构，提供安装、启动、扩展同步、备份与诊断指导，不包含个人收藏、数据库或凭据。

可以从 GitHub Release 下载 `stashmuse-agent-skill` 压缩包，并按照所用 AI Agent 的 Skill 导入方式安装。诊断脚本默认只读取状态，不会显示密钥内容；完整恢复数据库或永久清空回收站前仍会要求明确确认。

单独安装 Skill、但电脑上还没有应用源码时，Skill 会先说明将访问的 GitHub Release 与 npm registry，并在得到确认后运行 `scripts/bootstrap.sh`。脚本下载固定的公开版本、校验 SHA-256、完成构建并初始化本地数据库，且不会覆盖已有目录。

## 安全边界

- 这是单用户、本地优先应用，只应监听 `127.0.0.1`。不要直接部署到公网、开放局域网访问或通过隧道暴露；数据 API 没有面向公网多用户场景的登录系统。
- 不要提交 `.dev.vars`、`.wrangler/state`、备份 JSON、浏览器资料、配对码或运行日志。
- Chrome 扩展只应从本仓库的 `extension/` 目录以“加载已解压”方式安装。发布前请检查扩展权限与平台适配器变化。
- 若发现安全问题，请使用仓库的私密安全报告渠道；不要在公开 Issue 中粘贴密钥、Webhook、收藏内容或数据库。
