# 私人搭配助手 · DeepSeek 第一版

入口：本地 `/gallery` → 美妆穿搭 → 插画下方「私人搭配助手」。不改变其他主题入口和二级收藏列表。

## 已实现

- 输入色系、场合、季节、其他偏好，生成 2–3 套整体方案。
- 每套包含发型、美妆护肤、穿搭、美甲；缺少相应收藏时明确标注延伸建议，不生成适合概率。
- 使用已保留的美妆穿搭类收藏，不修改原收藏、分类和状态。
- 可选封面分析：按条件做轻量文本匹配、按四类轮流选取最多 8 张封面；不是全库视觉检索。
- 仅接受四个平台的公开图片 CDN 地址。链接送到 DeepSeek，由服务读取；不发送平台 Cookie，不下载视频、不做转写。
- 封面观察独立生成并验证来源 ID，再交给搭配步骤。标题、片段、封面观察的证据边界分别声明。
- 图片阶段超时/读取失败时自动回退到文字，展示原因和重新同步建议，不声称已看图片或视频。
- 引用卡片显示原笔记链接、封面（可访问时）、平台及证据类型。
- 整套方案缓存在本地 settings；完整成功的封面分析另缓存。条件、内容版本、封面 URL 变化会使方案缓存失效。「重新生成」绕过两级缓存。
- 旧调用不传 useImages 时默认纯文字；页面明确披露图片传输并允许关闭。

## 验证（2026-10-19）

- DeepSeek 真实搭配请求成功：34 条已保留收藏、30 条有片段，返回 3 套方案；来源均为真实已保留记录。重复请求复用缓存。
- 8 张当前候选小红书封面均返回 HTTP 403，DeepSeek 报图片下载失败。已经验证文字回退，并明确展示限制。需要重新同步有效封面后再验证真实收藏的视觉分析；重新同步也不保证平台允许外部读取。
- 用项目插画进行独立图片输入测试：deepseek-flash 返回 200，正确描述了短发与托腮姿势，确认模型图片接口可用。此测试不等于真实收藏图分析通过。
- URL 限制、最多 8 张、去重、四类覆盖、关键词匹配与稳定排序测试：`node scripts/test-outfit.mjs`。
- 跨来源请求 403、错误输入 400、空总结 422。
- 网页实测生成、原笔记卡片、失败提示和移动端布局。
- `npm run build` 通过。全项目 `tsc --noEmit` 仍存在此前已有的 `app/page.tsx:13` payload unknown 错误；本次未改动该后台文件。

## 边界

封面并非全文。未处理原视频、音频、逐字稿、用户衣橱、试衣图片或 JVE。AI 分析仍在 DeepSeek 云端完成，只把结果缓存本机，不是离线模型。
